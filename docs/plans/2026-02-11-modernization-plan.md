# Modernization Plan: `eth-hot-wallet` + `eth-lightwallet`

**Status:** proposed
**Date:** 2026-02-11
**Scope:** `eth-hot-wallet` (this repo) and the sibling fork `gkgoat1/eth-lightwallet`
(checkout at `~/Code/gorks/eth-lightwallet`).

## 0. Why

The app is a 2017–2020-era [react-boilerplate](https://github.com/react-boilerplate/react-boilerplate)
project that cannot be built or tested on a modern toolchain (Node ≥ 20, modern npm/yarn):

| Area | Current (broken/obsolete) | Target |
| --- | --- | --- |
| Language | ES6 + JSX via Babel 6 (`stage-0`!) | TypeScript (strict), `.ts/.tsx` |
| Bundler | webpack 3 + `babel-loader` + DLL plugin | **tsdown** (rolldown-powered; emits ESM + CJS + `.d.ts`) |
| Module format | Babel-transpiled ESM, CJS interop | **ESM-first**, dual ESM+CJS publishing for library parts |
| React | 15.6 | 18.x |
| State | `redux` 3 + `redux-saga` 0.15 + `immutable` + `react-router-redux` | Redux Toolkit 2 + `redux-saga` 1.x + **drop `immutable`** + `react-router` v6 |
| Ethereum | `web3` 0.20 + `eth-lightwallet` ^3.0.1 + vendored `ethjs-provider-signer` | `viem` (+ a **local** `eth-hot-wallet-keystore` adapter over the modernized lightwallet core) |
| Wallet core | npm `eth-lightwallet@3.0.1` (pulled from registry) | modernized `@gkg/eth-lightwallet` **4.0.0-based**, built with TS + tsdown |
| Tests | jest 20 + enzyme 2 (won't run on modern Node) | **vitest** + `@testing-library/react`; **Anvil** (Foundry) fork tests for chain I/O; **goldens** generated by the original code |
| Package manager | yarn 1 lockfile | pnpm (pinned via `packageManager` + Corepack) |
| Lint/format | eslint 3 + airbnb 15 | eslint 9 flat config + typescript-eslint + prettier |
| CI | none (only coveralls script) | GitHub Actions: lint → typecheck → unit → goldens → anvil (docker) → build |

## 1. Non-negotiables

1. **Preserve functionality.** Every user-visible behavior (vault create/restore, address
   generation, locking/unlocking, ETH + ERC-20 send, fiat rates, faucets) must be reachable
   and behave identically, unless a change is explicitly listed in §9.
2. **Keystore compatibility is sacred.** A vault serialized by the original app
   (localStorage dump / seed restore) must unlock in the modernized app and produce **the
   same addresses and the same signed transactions**. This is proven by golden tests, not by
   reading the code.
3. **CommonJS usability.** The keystore library must remain consumable from CJS
   (`require()` works, no top-level await in the CJS path). The webapp ships ESM to browsers.
4. **If not compromised.** Where the plan says "if not compromised", the referenced original
   artifact (git history, npm tarball) must pass the integrity checks in §2 before it is
   used as a reference oracle or upgraded base. Current findings: **both pass today** — see
   §2.3 — but the checks are repeatable steps in the plan, not one-time assertions.
5. **Incremental landings.** Each phase in §4 lands green on CI by itself. No big-bang PR.

## 3. Testing strategy (the backbone of "preserving functionality")

### 3.1 Golden / comparison tests (original code as oracle)

Generate fixtures **with the original, verified code** before changing anything:

* Keystore goldens (run under old Node against npm `eth-lightwallet@3.0.1` **and** the fork
  at 4.0.0):
  * `generateRandomSeed(entropy)` shape validation;
  * `createVault({password, seedPhrase, hdPathString})` → full serialized vault JSON for a
    **fixed seed + fixed password** (scrypt params captured: logN=14, r=8, p=1, dklen=32 —
    confirmed in source);
  * `keyFromPassword` + `generateNewAddress(pwDerivedKey, n)` → first 5 addresses for the
    fixed vault (these are deterministic given seed+path);
  * `signing.signTransaction` for 3 canned txs (ETH transfer, ERC-20 `transfer`, contract
    deploy-less raw tx) → expected raw signed hex;
  * `keystore.deserialize(serialize(x))` round-trip;
  * v3→v4 vault `upgrade.js` path (from the 4.0.0 tree).
* App-level goldens: run the original jest 20 suite once under old Node and snapshot its
  results (it reportedly passed at HEAD) so sagas/reducers/selectors can be diffed against
  their ports.

Goldens live in `test/goldens/**` (both repos) and are checked in. The modernized
implementations must reproduce them **bit-for-bit** for addresses/signatures, and
semantically for encrypted JSON (ciphertext differs per run; decrypt-and-compare).

### 3.2 Anvil integration tests

* Use [Foundry Anvil](https://book.getfoundry.sh/anvil/) as a local in-process-ish chain:
  * a small TS helper (`test/anvil.ts`) that spawns `anvil --port 0 --silent`, waits for
    readiness, and exposes an HTTP endpoint + funded dev accounts;
  * tests: fund a wallet address, check `getBalance`/`eth_call`, send a raw signed ETH
    transfer, send an ERC-20 `transfer` against a locally deployed test token (compile a
    minimal ERC-20 once with `solc` or check in prebuilt bytecode — prefer checked-in
    bytecode + ABI to avoid a solc dependency);
  * **comparison mode**: the same test vectors are signed by (a) the original
    `eth-lightwallet` + web3 0.20 path and (b) the modernized path, then both submitted to
    Anvil — receipts must match.
* Anvil is a **prerequisite**: if the `anvil` binary is missing (or, on CI, the Foundry
  toolchain container is unavailable), the suite fails closed with a clear message instead
  of silently skipping.
* Local dev: document `curl -L https://foundry.paradigm.xyz | bash && foundryup` (or
  `brew install foundry`); CI uses the official Foundry toolchain action / docker image.

### 3.3 Unit + component tests

* vitest for all unit tests; `@testing-library/react` + jsdom for components.
* Port the existing 70 jest tests one-for-one first (mechanical: jest→vitest,
  enzyme→RTL), then extend coverage for the new adapter layer (§5).
* Keep the old coverage thresholds as a *goal*, not a gate, during transition; ratchet them
  back up once ports land.

## 5. Library work

### 5.1 Modernized `eth-lightwallet` — Git dependency owned by the parallel session

**Ownership.** The keystore port is executed by the parallel session (`t-11d7`) inside the
`gkgoat1/eth-lightwallet` repo (modernization branch there), **not** in this repository.
This section is the *contract* this repo places on that work, plus the transition strategy
for adopting it. The technical requirements below were forwarded to that session via the pi
link; `test/goldens/**` produced here in Phase 2 are the shared acceptance fixtures.

**Dependency transition strategy (this repo):**

1. **Keep** `"eth-lightwallet": "^3.0.1"` (npm) as the imported package throughout
   Phases 1–4.
2. As soon as the fork's modernization branch produces a buildable artifact, add it
   **alongside** as a Git dependency under an alias, pinned to an exact commit:
   `"eth-lightwallet-next": "github:gkgoat1/eth-lightwallet#<sha>"`. Pin by commit, not
   branch; advance the pin deliberately (one PR per bump) so regressions are bisectable.
3. Run the golden + Anvil comparison suites against `eth-lightwallet-next` (sign old vs
   new, decrypt old vaults with new lib, etc.). **Gate:** all green.
4. Only then flip app imports from `eth-lightwallet` to the modernized package, and remove
   the npm `3.0.1` dependency in the same PR. The alias is dropped once the package is
   published (or the git dep is renamed to the real name) in Phase 7.
5. Rollback: revert the import flip; the npm dep stays in `package.json` until the
   modernized package has survived a full release cycle of the app.

**Contract on the fork's deliverable** (requirements the parallel session is implementing;
verified here before the import flip):

* Source base: fork at 4.0.0 (`lib/{assert,encryption,keystore,signing,txutils,upgrade}.js`,
  ~870 LOC), ported file-by-file to TypeScript, preserving public API:
  `keystore` (createVault, generateRandomSeed, isSeedValid, keyFromPassword,
  generateNewAddress, getAddresses, serialize/deserialize, signTransaction,
  passwordProvider), `signing`, `txutils`, `encryption`, `upgrade`.
* Dependency swaps (behavior-preserving, verified by goldens):
  * `bitcore-lib` + `bitcore-mnemonic` → **`@scure/bip39`** (audit-first, audited) for
    mnemonic + seed; keep HD derivation via **`@scure/bip32`**.
    *Compatibility note:* lightwallet's `generateRandomSeed` historically produced BIP39
    mnemonics; validate against goldens. Randomness via `@noble/hashes`/`crypto.getRandomValues`.
  * ~~`crypto-js` → `@noble/ciphers`~~ **CORRECTED (t-11d7, 2026-02-11):** the v3 vault
    format uses **no AES at all** — `encryption.js`/`keystore.js` are pure tweetnacl
    (`secretbox` XSalsa20-Poly1305 for seed/HD-root/keys; `nacl.box` for the asymmetric
    module). Keep **`tweetnacl@1.0.x`** (stable, pure JS, isomorphic); `@noble/ciphers` has
    no xsalsa20-poly1305. `crypto-js` survives only in `upgrade.js`'s v1 path
    (PBKDF2-HMAC-SHA1, 150 iters; AES-256-CBC via EVP_BytesToKey-style KDF; SHA3('') of the
    derived key as password check), keyed by fixtures `test/fixtures/lightwallet.json` (v1)
    and `lightwalletv2.json` (v2); may be reimplemented on `@noble/ciphers` AES-CBC +
    `@noble/hashes` PBKDF2 — goldens decide.
  * `scrypt-async` → **`@noble/hashes` scrypt** with **identical params, confirmed in
    source by t-11d7: `logN=14` (n=16384), r=8, p=1, dklen=32**
    (`lib/keystore.js#deriveKeyFromPasswordAndSalt`). ⚠️ n=1024 vaults would be
    incompatible with every existing lightwallet vault.
  * `ethereumjs-tx` 1.x / `ethereumjs-util` 6.x → **`@ethereumjs/tx` 5.x + `@ethereumjs/util`
    9.x** with **legacy signing retained**. **CORRECTED (t-11d7):** ethereumjs-tx@1 signs
    **pre-EIP-155 by default** (v = recid + 27, no chainId) and `keystore.js` never passes
    one — fixtures pin `rawSignedTx` with v=27/28. Default must stay non-EIP-155; EIP-155
    only when the caller explicitly supplies `chainId`.
  * `elliptic` (direct) → `@noble/curves/secp256k1` (transitively via scure).
  * drop `web3` 0.20 dependency entirely (it was only used for `toWei`-style helpers in
    examples).
* API surface (confirmed with t-11d7): `module.exports = { txutils, encryption, signing,
  keystore, upgrade }` exactly as 4.0.0, with ESM named+default exports mapping to it.
  3.0.1 consumers touching `keystore.Signing`/`keystore.TxUtils` are served by the
  top-level `signing`/`txutils` exports. **Behavior note:** 4.0.0 makes `hdPathString`
  **required** in `createVault` (3.0.1 defaulted to `m/0'/0'/0'`) — **keep 4.0.0 strict
  behavior** (decided 2026-02-11; hot-wallet already passes `hdPathString` explicitly, and
  silently defaulting a derivation path is a footgun).
* Build with **tsdown**: `entry: src/index.ts`, outputs:
  * `dist/index.js` (ESM) + `dist/index.cjs` (CJS) + `dist/index.d.ts`;
  * `package.json` with `"type": "module"`, `exports` map:
    `{ ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js", "require": "./dist/index.cjs" } }`;
  * browser-safe: no Node-only builtins on the default path (noble/scure are isomorphic).
* Tests: vitest unit tests ported from `test/*.js` (mocha) + goldens + Anvil comparison
  (sign with old vs new, submit both).
* Tests in the fork: vitest unit tests ported from `test/*.js` (mocha) + the shared goldens
  from this repo's `test/goldens/**` (copied into the fork's `test/golden-external/` with
  provenance) + Anvil comparison (sign with old vs new, submit both). Goldens flow
  **bidirectionally**: the fork also publishes its regenerated goldens (fixed salt+password
  serialized vault, first-5 addresses, 3 signed legacy txs, v1/v2→v3 upgrade outputs) which
  this repo re-runs.
* Release (fork repo's responsibility): scoped package (`@gkg/eth-lightwallet` or similar);
  until published, this repo consumes the **Git dependency** per the transition strategy
  above. Publishing happens from `gkgoat1/eth-lightwallet`, not from this repo.

### 5.2 `packages/web3-adapter` — drop-in for web3 0.20 + SignerProvider

The app today does: `new Web3(new SignerProvider(rpcUrl, { signTransaction,
accounts }))`, `web3.eth.getBalance`, `web3.eth.sendTransaction`,
`web3.eth.contract(abi).at(addr).transfer.sendTransaction(...)`, plus `toWei/fromWei`.

Provide a typed facade with exactly the surface the sagas use, implemented on **viem**:

* `createWalletClient({ chain, transport: http(rpcUrl), account: keystoreAccount })` where
  `keystoreAccount = toAccount({ address, signTransaction })` wrapping
  `keystore.signTransaction` (respecting `passwordProvider` prompt flow — the saga swaps
  `keystore.passwordProvider` around sends; preserve that mechanism or replace with an
  explicit `unlock(password)` scoped API, with the prompt behavior unchanged from the
  user's perspective);
* helpers: `getBalance(address)`, `sendEth({from,to,value,gasPrice})`,
  `erc20.transfer({contract,to,amount,from,gasPrice})`, `call` for `balanceOf`/`decimals`,
  `toWei/fromWei` (re-export viem `parseEther/formatEther` + the app's `unitConverter`
  semantics — goldens for unit conversions exist in `app/utils/unitConverter.js` tests);
* gas-price + nonce handling to match web3 0.20 behavior the UI expects (the app lets the
  user set gas price; keep that).
* tsdown dual ESM/CJS + d.ts, same as keystore.

## 6. App migration (Phase 5)

Order matters; do these as separate commits inside the phase:

1. **tsconfig + allowJs**: introduce `tsconfig.json` (`strict: true`, `module: ESNext`,
   `moduleResolution: bundler`, `jsx: react-jsx`, `paths` for the old
   `containers/…`/`components/…`/`utils/…` absolute imports so imports don't change yet).
2. **Replace the build**: remove webpack 3 + DLL + babel 6 configs (`internals/webpack`,
   `.babelrc`/`package.json#babel`, `build:dll` postinstall). Serve/build the SPA with
   **rolldown-vite or vite** for the browser bundle. (tsdown is used for the *libraries*;
   the app needs an html/asset pipeline — vite-family is the tsdown-consistent choice.)
3. **Port utils → TS** (`app/utils/*`): `unitConverter`, `crypto`, `common`, `request`,
   `contracts/abi`. These are leaf modules with existing tests — port tests first, watch
   them stay green.
4. **Port store plumbing → TS**: reducers/selectors/actions per container, then sagas
   (`Header/saga.js` 487 LOC, `HomePage/saga.js` 393 LOC are the big ones). Swap
   `web3`/`SignerProvider` imports for `packages/web3-adapter`. Keep the `eth-lightwallet`
   import on npm 3.0.1 until the §5.1 gate passes, then flip to the modernized package.
5. **Port components → TSX** (JSX bodies unchanged; add prop types as TS interfaces;
   `PropTypes` may be deleted as components are ported).
6. **Delete**: `app/vendor/ethjs-provider-signer` (superseded by web3-adapter),
   `babel-polyfill`, `intl` polyfill (modern browsers), `whatwg-fetch` polyfill, and any
   vendor shims made obsolete.

## 7. Framework upgrades (Phase 6)

* **React 15 → 18**: `createRoot`, remove `react-loadable` (use `React.lazy` + `Suspense`),
  `react-helmet` → `react-helmet-async` (or native `<title>` management).
* **react-router-redux 4 + react-router-dom 4 → react-router v6**: routes are few
  (`/`, `/token`, `*` NotFound); replace `ConnectedRouter`/route-synced store with v6
  `createBrowserRouter` and read route state via hooks.
* **redux 3 + redux-saga 0.15 + immutable + redux-immutable → Redux Toolkit 2 + redux-saga
  1.x, plain JS objects**: this is the riskiest behavioral change. Do it container-by-
  container; selectors keep their public signatures; goldens for reducer/action pairs
  (record reducer outputs for the app's action corpus with the old stack, compare after).
* **styled-components 2 → 6**: mostly drop-in; check `injectGlobal` → `createGlobalStyle`.
* **antd 3 → 5**: biggest UI diff risk. Wrap antd usage behind the app's own components
  (it already largely is — `app/components/*`); upgrade with visual spot-checks; forms in
  antd 5 differ (no `Form.create`) — the affected components are the modals
  (`GenerateWalletModal`, `RestoreWalletModal`, `SendTokenView`).
* **i18n**: `react-intl` is present but mostly disabled (`LanguageProvider` commented out).
  Keep disabled; do not re-introduce during migration.
* **history 4 →** drop (router v6 owns history).

## 9. Known latent bugs in the original (fix during migration, with regression tests)

Per repo policy, latent bugs get fixed, not preserved — but each fix is called out and
covered by a test that would have failed on the old code:

1. **`app/containers/Header/saga.js:153`** — `updateTokenInfo(keystore.getAddresses,
   action.tokenInfo)` passes the **method reference** instead of calling it
   (`keystore.getAddresses()`). The reducer then stores `addressMap: <function>` via
   `fromJS`, effectively clearing/งcorrupting the address list whenever the network changes
   and a keystore exists. Fix: call the method (or `select` the keystore and read
   addresses); add a saga test asserting `updateTokenInfo` receives an array.
2. Audit pass for more during Phase 5/6 (each ported module gets a "bug notes" section in
   its commit message if a behavioral deviation from the original is intentional).

Any other behavior change must be listed here before merge; otherwise behavior is preserved.

## 10. Risks & mitigations

| Risk | Mitigation |
| --- | --- |
| Golden fixtures can't be generated because original code won't run | Old-Node container/prefix; as last resort, hand-derive from fixtures in lightwallet `test/fixtures` (they ship known vault JSONs) |
| scrypt/AES params subtly differ → vaults undecryptable | Goldens must include *decrypt the original's vault with the new lib* and vice versa; CI gate |
| HD path / address derivation differs (bitcore→scure) | Address-list goldens per fixed seed; any mismatch blocks Phase 3 |
| Legacy-tx signing differs (@ethereumjs/tx major bump) | Raw-signed-hex goldens + Anvil receipt comparison |
| antd 3→5 visual regressions | Component-level isolation; screenshot diffs optional; accept minor visual drift, no functional drift |
| redux-immutable removal breaks selectors | Selector-level goldens; container-by-container port |
| Parallel lightwallet session diverges from the contract (API drift, no CJS build, moving branch) | Git dep pinned by commit; §5.1 gate (goldens + Anvil + CJS smoke) must pass before the import flip; npm 3.0.1 stays until then |
| Plan written against wrong crypto facts (AES-CTR/scrypt-n assumptions) | Corrected 2026-02-11 per t-11d7's source-verified report (v3 = tweetnacl secretbox; scrypt logN=14; pre-EIP-155 default signing). Goldens, not prose, are the final arbiter |
| `crypto-js` quirks (non-standard KDF usage in `encryption.js`) | Read `lib/encryption.js` carefully; noble replacements must match byte-for-byte — covered by vault goldens |
| Publishing scope/name availability | Decide scope early (`npm view`); until decided, packages stay private/workspace-only |
